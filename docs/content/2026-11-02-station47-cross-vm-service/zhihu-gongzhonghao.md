# 知乎/公众号长文:两个虚拟机怎么说话——站 47 跨 VM 服务手记

## 标题候选

- 《十次取证全对,答案却在调度器:跨 VM 共享窗的翻案记》
- 《共享窗的安全不在密码学,在配置权》

## 正文骨架

### 一、机制本身不复杂

宿主在物理内存的空档刻 2MB,stage-2 双映给两个 VM;协议是
代际槽位:{seq, ack, text}——写方先备货后递增序号,消费方见到
"ack≠seq"就读走并回执。任何时刻入场皆真,不用握手。零拷:
窗口直写,连宿主中继都没有(参考实现是单拷,我们记档差异)。

### 二、第一层坑:静默驻车

新块只加了内核页表,忘了 per-process 半区。壳的 demo 跑在
per-process 表+SP_EL0 语境,写窗直接落进"当前 EL SP0 同步
异常"向量槽——那个槽的默认动作是静默驻车:不打印、不 panic、
cat 都叫不醒。-d int 才看见真相:ESR 0x25,FAR 0x41200010,
落点是 park 循环的 WFI。这是本项目站 28 的老家族,第八次现形。

### 三、第二层坑:仪器全绿而系统不工作

修完映射,交换还是不通。上了 gdb 十连取证:物理地址别名
(seq=1 真的在)、双侧 stage-2 描述符逐字节同值、vCPU 存档 PC
恰好落在轮询指令上、寄存器 x5=窗口地址、自写回环活——每一项
都正确。每项都正确而系统不工作,答案只能在架构规则里:
站 19D 的四行字——console 按 VM 独占,谁持前台谁独享 CPU,
后台 VM 零切片。vm0 持前台写窗,vm1 后台永远不跑,永远看不见。
连它的 vtimer 都不会注入一个没被调度的 vCPU。

### 四、依律重铸

正确的 demo 形状:开机常驻的静默生产者(真交换才出声,安静
承诺不破),vm1 侧的消费者命令,和一记 host-owner 窗舞——
消费者吃完把 console 交还宿主,owner=NULL,双 VM 并跑,生产者
的回执打印随即到达。站在规则上设计,一次通过。

### 五、复盘

两条纪律进账:①stage-1 新块必须双侧(内核半区+per-process
半区),单侧=静默驻车;②仪器全绿而系统不工作时,下一个要审
的对象是架构规则,不是更多仪器。
