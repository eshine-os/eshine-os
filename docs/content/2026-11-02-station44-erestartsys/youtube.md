# YouTube 脚本:站 44——信号打断之后,内核替用户撒的善意谎言

**时长**:约 7 分钟 | **形式**:屏幕录制 + 画外音

## 冷开场(0:00-0:40)

你写过这个循环吗?while 重试,if errno == EINTR continue。
为什么内核不自己处理"被打断"?其实 Linux 处理了——ERESTARTSYS,
一个从不越过 ABI 的内核内部值。这集把它装进我们自己的 RTOS。

## 机制(0:40-3:00)

- 白板:svc 异常入口,ELR 指向 svc 的下一条指令。
- 两笔手术:elr 减 4=重取 svc;x0 槽不写=保入参,同参再入。
- 屏幕演示:源码四行,分发器单点。
- 强调:这是内核内部值 -512,用户永远看不到它。

## 机制咬合(3:00-4:30)

- 白板:信号投递的整帧存档(站 32)+ 重启手术赶在存档前落笔。
- handler 归还 → sigreturn 恢复整帧 → eret 落在回拨后的 elr。
- 金句:零新机器,两个旧机制咬合成一个新语义。

## 判据巧思(4:30-6:15)

- 屏幕演示:sigdemo 运行,handler 打印,然后 "-EAGAIN ok"。
- 讲解:handler 自己戳字,重启再入的入口校验立刻失配。
- 一判决两事:elr 没回拨=错窗垃圾;x0 没保住=野访 panic。
- 反面雷:重启破了,旧脸 -4 落 FAIL 行,门红自抓。

## 收尾(6:15-7:00)

- 不重启的与重启的一样重要:sigsuspend 特例、poll never-restart、
  sem/msg 吸收重挂。语义表完整。
- 下集预告:调度分区化(APS+MPRT)——把"谁都不能饿死"
  从纪律变成机制。
