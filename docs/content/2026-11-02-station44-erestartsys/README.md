# 站 44:ERESTARTSYS 可重启系统调用(内容包口径)

## 一句话

信号打断阻塞中的系统调用,调用方凭什么当无事发生?Linux 的答案
是 ERESTARTSYS:回拨 PC、保住入参,handler 归还后 svc 重执行——
本站把这个语义装进 eshine-rtos,老 -EINTR 契约退役。

## 技术叙事(对外讲什么)

1. **为什么 -EINTR 直返是偷懒**:调用方拿到假错要自己认出"其实
   没发生什么"并重试——每个用户都要写一遍 if (errno == EINTR)
   retry。内核既然知道真相,就该自己吞下这口气:回拨 elr-4
   (ELR 本指 svc 的下一指令),x0 槽不写(入参原样=同参再入)。
2. **帧手术连锁**:信号投递本来就是整帧 272B 存档+改写——重启
   的回拨只要赶在存档前落笔,handler 归还经 sigreturn 恢复的
   自然就是回拨后的帧。两个机制咬合,一处新手术零新机器。
3. **判据的巧**:判据藏在 handler 里——handler 自己把 futex 字
   戳成 1,重启再入的入口值校验立刻 -EAGAIN。这一判两事:
   elr 没回拨,执行的会是 svc 后面的错窗垃圾;x0 没保住,拿
   -512 当地址早就野访 panic 了。
4. **特例的诚实**:sigsuspend 恒返 -EINTR 是 POSIX 特例(Linux
   同律),留着;poll 家族 never-restart,留着;sem/msg 打断
   本就被 take 环吸收重挂,不生产重启。哪些机制不重启与哪些
   重启一样重要。

## 金句

- 可重启语义 = 内核替用户吞下"其实没事发生"这句话。
- 帧手术的纪律是动什么还什么;可重启的纪律是假装什么都没动。
