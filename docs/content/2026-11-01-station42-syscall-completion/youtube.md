# 站 42 · YouTube 口播稿

**[开场]**
eshine-os 第四十二站。这一站的源头,是站 41 收完之后的一次全面
对账:把参考内核的五百二十二个文件做机制白描普查,和我们三十
个文件的 RTOS 逐面比对,揪出了当初差距清单漏掉的一整层——
syscall 面。这一站按真 Linux 号补二十七个。

**[补了什么]**
调度器管理组全套:改优先级、改亲和、让出 CPU、查轮转间隔,连
nice 值的两向换算都做成线性自洽。信号面补齐:查挂起、换掩码
等待、备用信号栈。posix 定时器全家加 itimer,通知走 sigevent,
到底层还是骑在站 20 那台软定时器上——tick 回调语境不许调度,
投递走不带 rt_sched 的唤醒版。然后是 robust futex:持锁的线程
死了,内核在退出路径遍历它注册的链,把还在等锁的线程自动唤醒。
这个判据是活的:demo 里线程等锁,leader 持锁退出,等待者被死亡
唤醒。

**[第一颗雷:getpid]**
getpid 返回的,一直是任务池的槽号加一,不是进程 pid。壳为什么
二十八站全绿?因为壳任务恰好占着池槽零,而它的进程 pid 恰好也
是一——两个身份碰巧相等。直到我写 demo,子进程调 getpid,报
出五,真实 pid 是二。十四个站,没有人在一个 fork 子进程里调过
getpid。缺口一直在等第一个顾客。

**[第二颗雷:两种 child]**
clone 出来的线程,恢复点在 wrapper 的返回帧,栈是全新的。demo
里线程落回了父亲的 C 帧——编译器把字符串字面指针存在父亲帧的
sp 加 1304,新栈那个位置是野的,线程拿着 ASCII 字节当指针,
崩溃地址直接就是字符串内容。修法:clone 子必须立刻进一个自有
帧的入口函数,musl 的 __clone 一直就是这么干的。fork 子因为整
个栈被拷贝,没有这个约束。同一天,两种 child,两种纪律。
