1/ 用户报了两个 bug:RTOS shell 进去就刷心跳;Linux shell 非常卡顿。第一个好办,第二个把我按在了调试纪律的课堂上——我的第一个根因假设被自己的实验判了负。

2/ 第一嫌疑:每次 vCPU 进场都有一发全量 TLB flush 幸存(上一个站修风暴时只门控了另一发)。删掉重测:毫无改善。判负证据:900 字符 echo 秒回(~1800 个内联 MMIO 陷阱,不过 vcpu_run);异常日志清点 606/s 恰是 tick 三连的预期音量。退役保留,收益记"无实测增量"。

3/ 翻案:所有"慢命令"数字(40s/60s/90s)细看全是 read_until 的超时预算,不是执行时间。-d int 的 90 秒窗里 guest 全程 idle 打拍,fp 任务根本没跑——命令字节进了环,没人醒。

4/ 健康路径实测:打字回显 24/24 全 0ms;输入一旦送达,1e6 次双精度累加 0.04s。卡顿=输入蒸发:泊位后唤醒丢失,0ms 或 30s+ 两态,无中间态。这是纠缠五站五张脸的 [41] 闪断家族——这次由用户亲手报案。

5/ 两洞:①唤醒只认 RX 分类的泊位,而 Linux 恒 TIMER 分类——输入只能等它自己的定时器,深睡即秒级到永远;②推环与停泊出口窗竞态。修=输入⇒runnable 不变量:唤醒去分类门(WFI"pending 即醒"补全)+泊位落定复查。评审补 Dekker:双侧各补 dmb ish。

6/ 修完探针:深闲置 5s 后发命令 0.00s;大 dump 完泊位立即输入(旧脸 30s 的那条路径)0.00s。然后门禁把我抓了:[19] 两轮同折,prompt 只出 "rtos>"——尾空格滞环 20s。

7/ forensics 定谳:延迟冲刷每泊重臂 +20ms,RTOS 恰是 10ms 拍——2:1 相位活锁,fire 永远撞上下下拍唤醒边界。站二十三这门一直绿,全靠心跳打印首字符顺手冲掉滞留字节——我把心跳静默(用户令①),救场没了,活锁裸露。修:只首次武装。

8/ 紧接着 [53] 又折:prompt 被互插者从中间撕开("rtos>[vm1] vm1> ")。根因=fg 路径每字符"先冲上一字符"的透传残骸,与"整行原子"的注释宣称自相矛盾——半行永远 5 字符已流+1 滞环。撤之,整段原子。两雷同宗:门禁一直绿≠没有雷,是救场机制在掩盖它。79 门,[47] 零刷屏断言/[69] hb 注入/[76] 收紧,双绿收口。Apache-2.0,仓库见简介。
