# 一个"卡顿"报障的三层翻案:从 flush 风暴论到输入蒸发定谳

(eshine-os 从零打造记 · 第二十四站)

用户两条报障:RTOS shell 进去就刷心跳;Linux shell 非常卡顿。
第一条好办,第二条把我按在了调试纪律的课堂上——因为我的第一
个根因假设,被自己的实验判了负。

## 第一层:flush 风暴论(判负)

"Linux shell 卡顿"最先指向一个幸存者:每次 vCPU 进场都有一发
全量 `tlbi vmalls12e1is`——站十九修 TLB 风暴时只门控了 vttbr
侧那发,hcr 写后这发漏网。每泊→醒周期一发,四线程同步全量
flush,理论上足以把模拟速率砸穿。删掉,重测——**没有任何
改善。**

判负的证据链:900 字符的 echo 秒回(那可是 ~1800 个 MMIO 陷阱,
而 MMIO 是内联处理的,不过 vcpu_run——反证陷阱路径零 flush
税);-d int 异常日志逐类清点,606 次/秒恰是 RTOS tick 三连
异常的预期音量。假设判负,但退役保留:HCR 不涉翻译缓存,
`isb` 就够,这是站十九自己定下的不变量——只是收益记"无实测
增量",不冒领战功。

## 第二层:超时假象(翻案)

重看"慢命令"的数字:cat /proc/cpuinfo 40s、fp demo 90s——
细看全是 read_until 的**超时预算**,不是执行时间。-d int 的
90 秒"fp 窗"里,guest 全程在 idle 打拍,fp 任务根本没跑过:
命令字节进了环,没有人醒。

健康路径的真实测量:逐字符打字回显 24/24 全部 0ms;900 字符
echo 0.00s;输入一旦送达,fp demo **0.04 秒**跑完 1e6 次双精
度累加。卡顿的真相是**输入蒸发**:泊位后唤醒丢失,0ms 或
30 秒+ 两态分布,没有中间态。这正是纠缠了五个站、出现过五
张脸的 [41] 家族——这次是用户坐在终端前亲手报的案。

两个洞名状:①推环唤醒只认 RX 分类的泊位,而真 Linux 恒 armed
恒 TIMER 分类,输入只能等它自己的定时器——深睡就是秒级到永
远;②推环与停泊出口窗竞态,字节落进无主之环。

修法是"输入⇒runnable 不变量":唤醒去 reason 门(WFI 的
"pending 即醒"语义补全),泊位落定后再复查一遍出口窗内是否
进了字节。评审补了 Dekker:两侧都是普通读写,各补 `dmb ish`,
至少一侧必见对侧写。

修完的探针:vm0 深闲置 5 秒后发命令 0.00s;vm2 深闲置后
0.00s;大 dump 完泊位立刻输入——旧脸 30 秒的那条路径——
0.00s。

## 第三层:两个被门禁抓出来的雷

A 块把心跳改成"只在壳自主睡时说话"(提示符零刷屏,加 hb 命令
按需打印)之后,门禁 [19] 两轮同折:prompt 只出 "rtos>",
**尾空格滞环 20 秒**。forensics(vmtrail 的 ev12 now 减 ev1
cval 可以直接实算唤醒延迟)加原始字节分析,挖出一个相位活锁:
站二十三的延迟冲刷每泊重臂 +20ms,而 RTOS 恰是 10ms 拍——
2:1 相位锁死,fire 时刻永远撞上下下拍的唤醒边界,再泊又先
重臂后扫描,尾字符永久滞环。**站二十三这门一直绿,全靠
心跳打印的首字符顺手把滞留字节冲掉**——我把心跳静默,救场
没了,活锁裸露。修:只首次武装,过期死线保留,下一泊定瞬间
即收。

刚修完,[53] 又折:prompt 被 vm1 的 prompt 从中间撕开
("rtos>[vm1] vm1> ")。再挖:fg 路径的每字符"先冲上一字符"
是站二十二逐字符透传的残骸,和注释里宣称的"整行原子"自相
矛盾——半行永远有 5 字符已流+1 字符滞环,20ms 冲刷窗就是
互插者的落缝之窗。撤前置发射,fg 字符全量入环整段原子,
两雷同宗:**门禁一直绿≠没有雷,是救场机制在掩盖它。**

## 收口

79 门零新增:[47] 加零自发心跳断言(提示符安静成为判据)、
[69] 改 hb 注入(tick 严格递增,vm0 在 vm2 靴流内真实行进的
主动活证)、[76] 超时 30s→10s 收紧(大 dump 后泊位输入,
正是输入蒸发脸的复现器)、[37] ipidemo 异步化(壳不再以睡态
跑 demo)。对抗评审 12 findings 全 CONFIRMED 全折叠,其中
一记顺手雷:vcpu_flush_all_tables 的清零循环还停在站十九的
三核,CPU3 的账从没清过。

残余如实记档:[41] 家族的 vtimer 侧真凶仍未根除——本站只是
把交互面和它解耦。静默的 tick 停摆还会偶发,[69] 的递增判据
会把它以"相邻 hb 同值"之形抓出来。下一个站,唤醒架构的
架构性收口。
