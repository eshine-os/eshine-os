# 第二十四站内容包:console 响应性(心跳按需 / 输入唤醒不变量)

口径(README 索引):
- **A 心跳按需**(用户令"进入 rtos shell 不要一直打印"):心跳
  只在壳自主睡(RT_SLEEP)时说话——提示符交互零刷屏(探针
  3.5s 零行,旧版 6-7 行);`hb` 命令按需打一行 alive
  ("输入命令再打印"的字面实现);sleep 窗语义保全([24] 门
  判据不动)。
- **B 输入⇒runnable 不变量**(用户令"linux shell 非常卡顿"):
  真根因**不是执行慢是输入蒸发**——健康路径 0ms(fp 0.04s/
  900 字符 echo 0.00s/唤醒 33µs),所有"慢命令"数字全是超时
  假象。两洞:①推环唤醒只认 RX 分类而真 Linux 恒 TIMER 停泊
  (pending vSPI 全盲);②推环与停泊出口窗竞态。修=唤醒去
  reason 门+泊位落定复查。探针:深闲置后输入 0.00s(旧脸
  30s+)。
- **C flush 幸存者退役**:站十九不变量补完——进场全量 tlbi
  幸存者(站十九只门了 vttbr 侧)退役;**判负实验诚实入档**
  (风暴论被 -d int+E4 反证,QEMU 此路径实为廉价,保留理由是
  不变量正确性非实测收益);评审顺手雷:vcpu_flush_all_tables
  清零循环停在站十九三核,CPU3 账从未清过——扩四核。
- **实现期两雷(门禁自抓)**:①延迟冲刷相位活锁——每泊重臂
  +20ms 对 RTOS 10ms 拍恰 2:1 相位锁死,尾字符永久滞环;站
  二十三此门一直绿全靠心跳打印首字符的意外救场,A 块静默
  心跳后裸露([19] 5/5 复现);修=只首次武装。②fg 前置发射
  撕缝——每字符先冲上一字符(透传残骸,与"整行原子"注释
  自相矛盾),半行必有 5+1 滞环,20ms 窗=互插者落缝([53]
  "rtos>[vm1] vm1> " 撕裂);修=撤前置发射整段原子。
  **两雷同宗:门禁一直绿≠没有雷,是救场机制在掩盖它。**
- **评审**:12/12 CONFIRMED 全折叠(15 代理终局:断言按脸
  路由/[37] demo 期零刷屏断言/泵入口网 owner 面放开/Dekker
  dmb 对偶/热自旋门控/ev16 事件码/ipidemo 异步化)。
- **诊断方法论**:超时数字≠执行慢(细看 read_until 预算线);
  vmtrail 裸命令+ev1/ev12 cval/now 配对=唤醒延迟可直接实算;
  假设判负也是战果(先入档再翻案)。
- 门禁 79 不变(零新门,[24] 不动,[47] 零自发心跳断言,
