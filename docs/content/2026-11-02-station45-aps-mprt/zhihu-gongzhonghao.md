# 知乎/公众号长文:谁都不能饿死,谁都不能吃死——站 45 分区化手记

## 标题候选

- 《给实时内核装双预算:CPU 保证+内存上限》
- 《一个幻影分区炸了四个测试:站 45 的战雷复盘》

## 正文骨架

### 一、为什么分区化排进主线

混合关键性系统(车规域控的本职)的核心承诺:高优先级负载
保证拿到 CPU,低优先级负载不许吃死内存。参考实现内核有
1108 行的 k_aps.c(QNX 自适应分区的自研移植)和内存分区
k_apm.c——站 27 差距清单挂账,本站白描兑现。

### 二、APS:guarantee 与 steal

百分比预算分区,窗 20 tick 记账。争跑时 20% 分区实得 20%
(保证);没人要 CPU 时你随便跑(偷闲,记账回冲)。实现上
三件复用:tick 钩子记账、超标节流复用睡眠机器(等待原语
零新增)、偷闲判断扫描池。调度器只加了 30 行。

### 三、MPRT:一钩双面

记账点选在 VMA 声明——mmap 和 fork 恰好同走一个 declare
函数,一个钩子管住两条路。孙进程 fork 要把子的整个声明窗拷
进组,32 页 > 16 上限直接拒——内存隔离连 fork 一起管,这是
参考实现 resident 记账之外的站内形状(declare-time 模型,记档
差异)。

### 四、战雷:幻影分区 0

新字段 mpart 没进进程 create 的清理清单。BSS 零初值=0,而 0
恰是合法数组下标——每个 fork 儿都"入组"了一个不存在的分区
0,其上限是 0,于是所有 VMA 声明全被拒。症状四张脸:信号
demo 子无输出、另一 demo fork failed、管道 demo 读失败、
内存 demo 退账脸 wrong。冒烟把四张脸抓成一张全家福,归约出
一个根因、三个修复(字段入清单、identity VMA 走专口、fork
承继一行)。

### 五、复盘纪律

"新域入槽清单"是本项目的老纪律(本案第六次),但本案的新
教训是:**零初值恰好合法时,残值不是崩,是幻觉**——野指针
教你谦逊,合法下标教你怀疑一切。冒烟四失败互为镜像时,先
找一个根因,再谈四个修复;判据先于结论。
