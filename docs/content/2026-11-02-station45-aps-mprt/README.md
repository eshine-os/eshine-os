# 站 45:APS+MPRT 分区化(内容包口径)

## 一句话

谁都不能饿死,谁都不能吃死——本站给 eshine-rtos 装上双预算:
CPU 分区保证下限+空闲偷闲(APS),内存分区声明窗上限带 fork
隔离面(MPRT)。

## 技术叙事(对外讲什么)

1. **APS 的两个语义**:guarantee(20% 分区在争跑时实得 20%)+
   steal(没人要的 CPU 白给你)。窗 20 tick 记账、超标节流复用
   睡眠机器、偷闲时回冲记账——调度器只加了 30 行,没有新等待
   原语。
2. **MPRT 的单一咽喉**:记账点不在页面分配,而在 VMA 声明
   (mmap 与 fork 恰好同走一个函数)——一钩双面。孙进程 fork
   要把子的窗口全拷进组,32>16 直接拒:内存隔离连 fork 一起管。
3. **本站最硬的一课(战雷复盘)**:新字段没进 create 清单,槽
   复用带残值 0——而 BSS 的 0 恰是合法数组下标!于是每个 fork
   儿都撞上一个不存在的"幻影分区 0",四个测试连炸,一张脸
   各报一种错。冒烟的价值不是绿灯,是把"互为镜像的失败"抓成
   一张全家福,归约成一个根因。
4. **白描纪律**:参考实现的 k_aps.c 1108 行,我们落地 200 行——
   因为白描的是机制(百分比预算+tick 记账+超标门+偷闲),不是
   代码。分区 0=system 余量池、Σ≤100 纪律,这些是语义不是行数。

## 金句

- 预算分区的哲学:保证是下限不是上限,偷闲是权利不是漏洞。
- 冒烟抓到四个失败互为镜像时,先找一个根因,再谈四个修复。

## 数字

- 窗 20 tick=200ms;share 判据 20% 带 10-30 宽;偷闲窗 45 拍≥40
- 内存分区 16 页上限;mmap/fork 双拒面;退场全退 cur=0
- 门禁 126→129;冒烟 10/10(含炸后复绿)
