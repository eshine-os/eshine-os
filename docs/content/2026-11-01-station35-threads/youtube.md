# 站35 · YouTube 口播稿

**[开场]**
今天,eshine-os 第三十五站,线程。给 RTOS 装上真线程——不
是玩具线程库,是 musl 1.2.5 的 pthread_create 原生跑通:
四个线程争一把互斥锁,join 收齐,计数器等于十。但今天真正
值得讲的是另一件事:验证这站的时候,我们抓出了一个**潜伏
了七个站点的原子窗**。它从站 28 就存在,一直没有场景踩中,
直到线程给了它第一个受害者。

**[musl 契约]**
先说线程本身。内核要懂 pthread 吗?不需要。内核只需要
兑现 musl 在 aarch64 上的四条硬契约,读 musl 源码就能拿到:
clone 系统调用,子线程是父帧的整拷加 x0 等于零,栈指针用
musl 压好的那根;SETTLS,新线程的 TPIDR_EL0 等于传入的 tls
指针,musl 的 __pthread_self 读的就是这个寄存器,所以它
必须随任务切换存还;CHILD_CLEARTID,线程退出时内核写
星号 ctid 等于零并发一次 futex 唤醒——pthread_join 靠的
用户态 futex 就靠这一口收口。四条契约,一个 rt_thr.c,
门禁判据:四个线程 join 收齐,counter 十,分毫不差。

**[两脸]**
然后是雷。冒烟一度一半的次数挂死,两张完全不同的脸。第一张,
panic 脸:一个 EL0 数据访问异常,elr 落在任务切换弹栈代码的
一条指令上,ldr x5 方括号 x0 井号 672——加载新任务的用户栈
指针;far 等于 0x2a0,672 的十六进制本尊。第二张,无声脸:
任务标着"运行中"却永不执行,系统时钟爬行,靠一个兜底泵
每隔几秒救一拍,gdb 尸检里任务帧停在弹栈中途的位置。

**[根因]**
两张脸,一个根。站 28 有个设计:系统调用上下文开中断,
让阻塞调用可以被时钟抢占。这个设计没问题,问题在它配的
机器上——任务切换的帧伪造、簿记、弹栈,这一整段**没有
原子化**。弹栈弹到一半的时候,msr spsr_el1 已经把返回态
装成了新任务的 EL0;这个瞬间 tick 嵌进来,存下的就是一个
嵌合帧:elr 是内核弹栈代码的地址,psr 却是用户态。等这个
任务再被调度回来,一 eret——执行流**以 EL0 的身份回到了
弹栈代码中间**,手里 x0 是刚弹出来的新线程的零,去读
内核任务结构,far 0x2a0 就这么来的。

**[为什么潜伏七站]**
最有意思的问题是:这个窗口从站 28 就在,为什么七个站
都没爆?因为它爆发需要两个条件同时满足:tick 恰好落进
那个几十条指令的窗,并且**有个同优先级的竞争者让调度器
真的从弹栈中途把任务切走**。此前所有测试负载里,嵌套的
tick 全走"不切换"路径——窗口内直接返回 EL1 正常续跑,
无害。四个同优先级的线程,是第一个让"切走"真发生的
场景。竞态窗口的爆发规律就是这样:它等的是触发组合凑齐,
而负载演化总有一天凑齐它。

**[修]**
修法两枚掩码,一个原则:帧恢复机器不可重入。协作切换入口
在寄存器压栈之后、帧伪造之前补 msr daifset;EL0 返回宏的
头部同补。中断向量自己的弹栈本来就是硬件入口自动掩码的,
所以真正裸奔的只有这两处。站 28 的语义一点没损失:阻塞
泊位的 psr 是 C 侧显式写进帧的,和这个掩码无关;eret 会
自动从 psr 恢复用户的开中断态。修完,pt 法医四比四,全
冒烟五比五,九十四门两连绿。

**[教训]**
两条带走。第一,契约迁移要 grep 全部调用面:futex 超时从
ticks 字面迁到 timespec 指针,只改了一个 demo,sigdemo 里
还传着旧值,新契约下它成了野指针——冒烟当场抓。第二,
仪器先于判据:这次我们先被一个烧着四个核的遗留 QEMU 骗
了半轮,所有"冻结"测量都是在污染窗里跑出来的;又被自家
判据脚本的松锚骗了一轮。老铁律的价值不在念出来的时候,
在违反之后自我执行的时候。
