# 站28 收口 · X 8 连推

## 推 1(破案总览)
"回复在而 tick 冻结"——用户敲键盘还活着,内部时钟死了。以为是
一个 bug,取证后发现三个互相独立的真身共用这一个症状。系统软件
最贵的教训:症状同名 ≠ 根因同源。81 门双绿收口。

## 推 2(真身一:弹栈错库)
EL0→EL1h 切换汇编,栈指针有两个"库"(SP_EL0/SP_EL1)。旧代码
把弹栈的推进记错库:eret 后栈指针仍是旧顶,每切换一轮净漏 272B。
idle 的 8KB 引导栈 20 周期踩穿软定时器表。修=换库前抓现值,
留目标库弹到底。

## 推 3(差分采样)
怎么把嫌疑面从"整个调度器"缩到"一条切换路径"?剥掉 shell
交互,gdb 三次采样 idle 栈指针:纯 idle+tick 世界里纹丝不动
(0x40027130)。泄漏只随阻塞-唤醒周期走。笨办法,但证据会说话。

## 推 4(真身二:无主收尸)
虚拟定时器中断落在宿主自己的时间片里到点,三分支逻辑(睡客/
在途/无主)漏了第四类:可跑客的活火。被当无主收尸=物理中断
永挂 active+零注入,滴答永死。协作式内核装没看见继续跑——
死点比可见冻结早 40 秒。

## 推 5(看门狗捕活火)
tick 死后世界照常运转,等到演示冻死尸体都凉了。解法:轮询
rt_ticks(物理地址经宿主语境线程读),冻结即拉 16384 条决策环
——死亡现场必在环内。trail 两行(ev15→ev8)定谳,胜过一切
纸面推演。

## 推 6(修法自雷×2)
修复当晚被打脸两次:①补偏 +16,寄存器全串位,heartbeat 跳 0
地址;②(id<<4)|vi 对 vm0.vcpu0 打包值=0,和"未初始化"哨兵
撞车,修复把唯一受害者拒之门外。新修必配最小复现器,当晚抓回。

## 推 7(真身三:前世记忆)
VM 销毁重建,复位清单漏了后来新增的九个字段——包括 SCTLR。
新客带"MMU 已开"入场,引导清 .bss 抹掉正在翻译的页表,取向量
地址即无限自陷,单轮 -d int 日志 230MB。struct 每加字段,
复位清单必须同步加——这句纪律用七站绿灯换来,值。

## 推 8(站28 本体+下一站)
正题:shell 从内核任务升格 EL0 用户任务——两区 stage-1、EL0
异常蹦床、Linux arm64 标准 syscall ABI。81 门连续两轮全绿。
