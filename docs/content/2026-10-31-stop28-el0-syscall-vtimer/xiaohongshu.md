# 一个 bug 的脸,三个 bug 的真身 🐛🐛🐛

做 hypervisor 第 28 站,shell 升级成 EL0 用户态,门禁开始玄学:
睡门超时、演示冻死、二次引导装死,全是一个症状——**回复在而
tick 冻结**(键盘还活着,时钟死了)。

以为是一个 bug。收口取证才发现是三个独立的,还互相不认识:

❶ **弹栈弹错库**:切换汇编里栈指针有两个"库",弹栈推进记错
库,每轮漏 272B。idle 的 8KB 引导栈 20 周期后踩穿软定时器表💥

❷ **无主收尸**:定时器中断恰好在宿主自己的时间片里到点,被
当成"无主的"收尸——物理中断永挂 active、零注入,滴答永死⏰

❸ **帧复用带前世记忆**:VM 销毁重建的复位清单漏了 SCTLR,
新客带着"MMU 已开"入场,清 bss 抹掉正在用的页表,取向量地址
即风暴,-d int 单轮日志 230MB 📄

还有两个修法自雷:补偏 +16 让寄存器全串位;(id<<4)|vi 对
vm0.vcpu0 打包值=0,和哨兵撞车,修复代码把唯一受害者拒之门外😅

破案工具三件套:
· 差分采样(剥交互看栈指针,三采样不动=泄漏随阻塞周期走)
· rt_ticks 看门狗(轮询到冻结立刻拉 16384 条决策环,尸体还是热的)
· 全环 trail(两行日志定谳,胜过一切纸面推演)

81 门×2 轮全绿✅ 心法:症状同名≠根因同源;修法必配最小复现器,
当晚就被自己的复现器抓了两次😂
