# 站 68:58 挂脸族全案取证——五守卫、四把钥匙与一个迟到十四站的真凶

> 本站口径:README 案例纪要版。技术细节见
> docs/devlog/2026-11-05-station68-58family-forensics.md。

## 案情

vm0 引导 20-75% 概率挂死,三种死法:静默楔(零输出)、内核
panic(ELR 指着任务池数据当代码执行)、8.4MB 纯空格洪水(以
128 字节精确周期冲向串口)。另有 bsh 交互式 REPL 四分之一的
活率问题纠缠其间。十四个站一路带着这个"随机病"走到 68 站,
本站专场上门办案。

## 侦破四步

1. **第四镜升级**:QEMU gdb stub 的 VA 读会走"当前 CPU 的翻译
   体制"——EL2 语境下客户内存全读空。三把新钥匙:`monitor xp`
   物理读透传、stderr 合流(monitor 输出不在 stdout!)、每靴
   端口轮换(TIME_WAIT 竞态曾让整轮取证变成假象)。
2. **活体解剖三例**:panic 楔的 ELR=&pool[5](任务池槽当代码);
   静默楔的主核停在 guest_park、rt_ticks 冻在 8;洪水死在
   hello 首个 printf 的 "pid=" 处。
3. **守卫仪器化**:tick 扫描面四谓词(sp 栈域/ksp 恰等/READY
   队列可达/队链全审计)+writev 巨 iov 绊线。案发 10ms 内带全
   证 panic——不再依赖碰运气的活体捕获。
4. **守卫开火即定谳**:`queue poison: cpu 0 prio 1f wild
   0x4015e460`——**idle 伪任务被塞进了就绪队列**。每靴第一拍
   必现:IRQ 出口把"当前任务"排回队尾时,没认出 rt_cur 是
   引导语境就地转正的 idle——它不占池,却在 prio 31 落了户。

## 真凶画像

idle 入队后,空转时调度器把 idle 当真任务切进,eret 进陈旧的
引导帧;idle 的 next 指针字段与自家 FP 保存区重叠,队链写以它
为笔野喷——就绪队列尾指针野化后,新任务被链接到 BSS 任意地
址。三脸与 REPL 挂全部同根:恢复被毒的帧→返回地址=&pool[5]→
跳进池数据执行→主核楔死→定时器停→一切睡眠永睡。

## 修真与验证

单点修复:就绪队列入队加池域硬门(`rt_task_in_pool`)——伪
任务永不得入队。证效:队列毒五靴全消、boot 首次完整走通整条
governed 序列且零守卫开火。残余:fork 子"被醒而队链不可达"
的孤儿脸与 REPL 残面——守卫已武装,下次开火即分类指认写手。

## 方法论沉淀

- 仪器先于判据,判据先于结论;守卫自身要过冒烟(首版把设计
  常态当犯罪抓了 2/2,冒烟当场纠偏)。
- A/B 对照是修真的牙医椅:0/3 集中挂=回归嫌疑,1/3 随机挂=
  历史病。
- "healthy idle"单点读数必误判,ticks 双时点+四核全景才是
  判据。
