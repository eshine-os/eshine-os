# 站 43:观测面 + ppoll(内容包口径)

## 一句话

内核出问题时你唯一缺的是"看见它"——本站给 eshine-rtos 装上三只眼睛:
崩溃自动打调用链、ps 每行一句"挂在哪"、poll 让任务能等一组 fd。

## 技术叙事(对外讲什么)

1. **calltrace**:x29 帧指针链走查,16 帧保险丝+内核窗门(用户帧
   止步=域分离),挂 panic 钩子——EL1 abort 从此自带调用链,不再
   "打印一行 then 祝你好运"。ARM64 的 x29 约定让 FP 链走查天然
   可行,前提是每层函数没偷懒(我们的内核代码全程 frame pointer)。
2. **ps blk 归属列**:每个阻塞点打一个"挂在哪个原语"的标签
   (信号量/互斥/串口/睡眠/futex)。妙处:站 30 的消息等待本来
   就是信号量实现,归属列如实显示 sem——不造假档,复用就是复用。
   抓到一个自己的洞:futex 走 pend_q 不经信号量,漏标会显示上一次
   的陈旧标签,当场补。
3. **ppoll(73)**:Linux pollfd 是 {int fd; short events; short
   revents} 8 字节——events 在 +4。第一版我把 fd 的高 16 位当
   events 解析,事件掩码恒 0,POLLIN 永不命中;而服务器侧取证
   显示它全程如实回答"可读"。调用方失聪、被调方无辜——判据面
   指向的老戏码。wire 层一个 RT_FDOP_POLL,三个服务器(tty/
   ramfs/pipe)各答自己的可读脸,零新等待逻辑。

## 金句

- 观测面不是奢侈品,是取证成本的对数器:一屏调用链 vs 三小时
  静默腐坏法医。
- 归属列的最高境界是暴露机制复用:msg 等待显示 sem,因为站 30
  本来就是拿信号量实现的——诚实比好看重要。
