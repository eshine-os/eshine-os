1/ 追了四个站的悬案结案了:门禁每十轮闪断一次,vm1 等不到 "spinning...",客机健康。两个观察哨都没抓住它。这次开站按调试纪律第一步重读全量 TimeoutError dump——上一站我只看了 tail,把证据埋了。

2/ 证据长这样:"spinni[vm2] [   n 0.1339g17]"。vm1 的输出和 vm2 的 Linux 时间戳字节级互撕——vm2 的数字里嵌着 vm1 的 n 和 g。needle 不是没到,是被撕了。三案历史一次解释完。

3/ 根因读代码即见:console_puts 持锁,console_putc 不持锁。全树盘点,vuart 前台逐字符透传(每字符一次 MMIO 陷阱)是唯一高频裸写者——cpu0 上裸写,cpu1/2 上 vm2 持锁整行输出,锁拦不住锁外的写。

4/ 失败测试先行:vm2 靴流窗内 60 发 needle 行风暴。修复前 4+ 撕,含 "spinni|ng" 与 "[  n  g0.000000]" 双向字节撕裂实锤。然后修三层:原语持锁、前台改行缓冲('\n' 锁内整行原子)、停泊冲刷保键回显。输出行 0/60 碎。

5/ 然后自己的门禁抓住了我。A 轮在复活链炸出新撕裂:"[vm0] rtos> c[vm0] pu1: online"——per-VM 行缓冲被同 VM 两个 vCPU 共享,我的停泊冲刷把次核正在追加的行拦腰切断。旧代码反而没这毛病。

6/ 修:全 VM 静默判(同侪 vCPU 都停泊才冲)。教训单独入册:修并发 bug 时,新引入的路径会和旧路径共享同一份状态——不把共享面盘清楚,新路径就是下一个雷。这次是门禁双绿制度把它当场按住的。

7/ B 块收了个小而正的:软定时器(超时机器的定时器化)。回调跑在核 0 tick-ISR 语境——这里能引用一个架构级契约:我们的自旋锁持锁即屏本核中断,ISR 永远不可能在持锁任务上再入,打印原语天然 ISR 安全。

8/ swtdemo 三面判据:单发到点、周期×3 自停、以及"取消后的缺席"本身进判据。门禁 75→76,A+B 终构建连续两轮全绿,观察哨闭案撤销。残余如实入册:chardev 分块边界处回显仍可能碎,根治需 100Hz 宿主时钟(现 1Hz=泵量子),列远期。代码 Apache-2.0,仓库见简介。
