# 站37:mqueue、管道和长消息——顺便抓出一颗绿了三个站的潜雷

eshine-os 站 37 收口。这一站做 POSIX 队列族,但真正值得
写下来的是一颗潜伏了三个站的雷,和它的定谳方式。

## 一、三件套

- **mqueue**:命名优先级队列。高优先先出、同优先 FIFO,
  插入点找第一个严格更低优先者。阻塞复用第 17 站就建好的
  pend 机器——这是"等待逻辑只建一次"红利第 N 笔。语义上
  有个 POSIX 细节值得记:close 只降描述符面,**队列本体活
  到 unlink**。我第一版把 close 写成了销毁,冒烟当场用
  open/close/unlink 三拍序把 bug 打了出来。
- **pipe**:字节流双端。关键设计是**骑在站 31 的 resmgr
  机器上,零新 fd 线**——管道服务器是第三个内核服务器
  任务,fd 三元组 {coid, ocb} 走和 tty/ramfs 一模一样的
  wire ops。写端引用全关之后,READ 恒返 0,这就是 POSIX
  的 EOF 语义。
- **长消息+MsgRead 镜像**:消息线超过 64 字节自动走
  1024 字节长槽池;归还口只有"所有 used=0 位"——生命周期
  跟着消息本尊走,三口收回,一个不漏。MsgRead 镜像是
  参考实现里最有味道的一小块:接收者收到消息之后,还能按
  偏移回头再读发送者的缓冲——延迟访问,不是急拷。

## 二、绿了三个站的潜雷

pipedemo 第一跑必挂:子进程往管道里写,返回 -EBADF。
排查到服务器侧打探针,抓到现场:**fd 层的写函数从站 31
起就不往消息里填 ocb 字段。**为什么三个站都没事?因为
tty 和 ramfs 的 WRITE 处理根本不读 ocb——一个没人读的
契约字段,漏填可以绿很多年。第一个真读者(pipesrv 要按
端分发)上门的当天,雷爆了,也当天定谳了。

这条规律值得记:**契约字段的测试,唯一的真形式是找到
第一个消费者。**在那之前,字段只是碰巧没人看。
