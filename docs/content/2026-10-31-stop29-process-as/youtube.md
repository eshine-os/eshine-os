# 站29 · YouTube 口播稿

**[开场]**
"进程"这个词,我们在教科书里读了无数遍,但它的物理分量只有
自己造一次才知道:每个进程一个世界,写字节时碰不到别人的内存。
今天这一站,eshine-os 第二十九站,我们把上一站那个"名义上的
用户态"变成事实。

**[第一课:可达性矩阵]**
先说这站最有价值的教训。设计地址空间,第一件事不是查映射编码
表,是画一张"可达性矩阵":谁、在哪个语境、能看到哪块内存。
我们的第一版设计把"页池"——fork 拷贝和匿名页的后备——和
"用户 mmap 窗"放进了同一个 VA 区。结果 fork 的内核态页拷贝
当场撞墙:内核的 PGD 用户块已经剥掉,拷贝目标根本不可达。
翻案是一次 VA 分区:内核块恒驻每套表;页池自任"内核高半区",
所有地址空间里 EL1-only,用户永远看不见;.user 段和 mmap 窗
各立 per-process 表。一个问题,消掉一整类问题。

**[缺页上岗]**
上一站的 EL0 访问未映射页,处理方式是"诚实收尸":打印寄存器,
全机停机——当时注释里就写着 "see station-29"。今天它退役:
翻译错误先查本进程的 VMA 申报表,命中就补页,原地重执行;
镜像和栈补恒等页,匿名 mmap 补零页;申报外的野访照旧终态。
边界没有松,只是从"全部拒绝"变成了"按申报放行"。

**[fork 的分量]**
fork 是 eager 全拷:父进程已映的页,逐页拷进页池,子进程拿到
的是物理隔离的副本。它写自己的内存,再也不会碰到父亲的字节。
这就是 per-process 页表的存在意义。

**[exec 的形状]**
最有味道的是 exec。内核不读任何镜像字节——只把保存帧里的
pc、sp、x0 到 x3、psr 七个字直改掉,eret 回去就是新程序。
那谁读 ELF?用户态的 loader。参考实现参考机制里写得清楚:内核
里的 elf_load 无人调用。我们没有用户态 loader,就用"同段二
相函数"替代演示:二相函数打完招呼,再 exec 回 shell 续行,
闭环。

**[自雷×2]**
两个自己踩的雷,复现器当晚抓回。第一,exec 的 arg 打出来是 0:
syscall 分发器的"返回值写 x0"回写,覆掉了帧改写里的 arg——
修法是让 exec 返回 arg,新语境的 x0 本来就是返回值,一字两用。
第二,门禁锚带换行符,撞上串口的回车换行转义——判据锚要先
在串口实貌上过一遍。
