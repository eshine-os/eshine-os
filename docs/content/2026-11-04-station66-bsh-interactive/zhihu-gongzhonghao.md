# bsh 无参交互:一次"全案取证"的翻案

站 66,批次 F 第二站:用户令"务必实现无参交互"。

## "定格"的第一层翻案

bsh 不带参,直进 busybox ash——屏幕就此静止。深夜直觉说:挂死了。
取证说:没有。

gdb-multiarch 源级直读(这轮装的第四镜):vm0 的 tick 100Hz 照走、
27 号中断计数照涨、心跳任务的 wake_tick 与 rt_ticks 同步推进——
**vm0 的任务面活得好好的**。ash 呢?BLOCK 态、睡在 RX 等待位上,
等输入——完全合法的形态。

那为什么屏幕全静?第一主谋是**设计**:站 24A 的心跳门——壳不在
SLEEP 态时心跳静默(用户令"不要一直打印"),bsh 的壳父睡在 wait4,
心跳识趣地闭嘴。"定格"的观感,九成是这条设计门。

## 真断的窄门

九成是设计,一成是真雷:ash 等的 RX 中断永远不来。泵的设备事件
注入门写着 `wait_reason==TIMER && owner==v` 才注入——ash 睡 stdin
时 vm0 泊在 TIMER 上,一旦 owner 面缺席,33 号 UART 中断就被这道
站 24B 的设计排除面挡在门外。

修法很窄:RX 环里真有可取数据(过了使能门控)时,非 owner 的
TIMER 泊也醒。空环照旧不醒——站 20 的热自旋教训不动。

修完之后,交互链第一次点亮:一靴里 "sh: selftest: not found"
——ash 把探针的行吃进去解析执行了。铁证。

## 没有收口的尾款

活率 1/4。非确定的竞态,和站 58 引入的 boot 挂脸族(未定谳,20-75%
靴挂)纠缠在一起——断点形态每靴漂移。诚实的账记在 devlog:**交互
可靠化的前置是 58 族专场取证**。场景和门禁只收确定性面(sh -c 模式
11/11 绿);无参交互保留给用户上手试,exit 回 rtos>。

顺带沉淀的:第四镜(gdb-multiarch+符号直读)和一条教训——HMP 的
`xp` 读 MMIO 设备是假象,对照组证明的。对着坏仪器的取证是空对照。


## 定稿:行 REPL

常驻 ash 的路(修好中断链)走通了 1/4——非确定竞态和 58 挂脸族
纠缠,继续深潜的边际成本太高。站 66 的定稿换了一条思路:

**bsh 不带参,进"行 REPL"**:壳父自己读行(和主循环完全相同的
sys_read 单字符面——几十站门禁验证过的稳定输入面,带回显和退格),
每读一行就 fork 一个 sh -c 执行,空行退出回 rtos>。

体验上:打一行、执行一行、看到 ash> 提示符——完整的交互感。
机制上:全部构件都是已验证的确定性面(行编辑+sh -c),只是第一次
把它们组合起来。活率 3/4——剩下的 1/4 是 58 挂脸族(全局 boot
问题,连累所有功能,不是 REPL 的雷)。

一个惊喜:busybox 的 applet(echo/ls/cat/变量展开)在 sh -c 里
内联执行(NOFORK 特性),全活——`ls /etc` 直接列出 inittab/motd。
只有仓内其他二进制(/bin/hello 这种非 busybox 命令)走 execve
会 127(exec=用户态 loader 的红线,ash 不认识这条路)。

**变量不跨行**(每行是一个新 sh)是 REPL 的诚实边界;要持久会话
(export/环境跨行),前置还是那句话:58 族专场。

门禁 [183] 收了 sh -c+REPL 两面,场景 18/18。绕开竞态的最稳
办法不是修好它,是把路径换到已验证的稳定面上。
