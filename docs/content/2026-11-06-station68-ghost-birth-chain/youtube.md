# YouTube 分镜(站 68F:幽灵出生链封口)

标题:三个月的 panic:向量表没接的线,和回车砸中的引导尾

## 分镜

1. **冷开场(0:00-0:45)**:实机录屏——进 shell,按回车,
   panic:"bookkeep violation";再开一次机,同一个地址;
   再开一次,还是同一个地址。"竞态不会给你同一个地址。"
2. **指纹学(0:45-2:00)**:解释"跨靴同值"的取证价值:确定性
   地址意味着每靴在同一位置发生的设计路径。十六件排除镜头快
   剪(字段/臂点/EL2 面/窗检……全静默),案卷越来越薄。
3. **"悖论"(2:00-3:30)**:本片最想教你的一课。违例帧 psr=
   EL1t(内核用 SP_EL0 库)vs 现场 spsel=1——两页手稿对照:
   psr 是"被中断语境"的存照,spsel 是"处理语境"的现值,
   同一场异常的两张脸。取景框装错,证据全是噪声;我们如何
   差一点为它造一台"EL2 混合态检测器"(未建即被取代,是
   本站最划算的一次未做)。
4. **双栈库设计(3:30-5:00)**:白板讲解:内核任务跑 SP_EL1;
   EL0 系统调用处理跑 SPSel=0(活栈=SP_EL0 库=任务自己的
   内核 C 栈),SP_EL1 驻 32B 蹦床。ARM 向量表 16 槽=
   "从哪来+当时用哪个栈"的完整谓词——数给我们看:EL0 来的
   (接了)、EL1h 来的(接了)、EL1+SPSel=0 来的——**没接**。
5. **案发回放(5:00-7:00)**:动画:系统调用处理中开中断→
   节拍落窗→硬件选 "Current EL, SP_EL0" 槽→入场强制
   SPSel=1→272B 帧压上 32B 蹦床→簿记把蹦床地址写进
   saved-sp→复活时 eret 携 EL1t 回 SPSel=0,活栈=别人的
   用户栈→幽灵跑内核 C→下个节拍又取同槽→自我复制。历史
   悬案对照:站 32"别家函数的字面"、站 68"复合帧"——
   日生缺陷的下游全部归位。
6. **修真(7:00-8:30)**:两件配对,代码走读:guest_irq_sp0
   改道(渡回自己的栈再压帧)+ .Lel1 库还(复活时把帧顶
   预还 SP_EL0 库)。强调"配对"——只改道不还库,幽灵换
   个姿势复活。
7. **验证与洋葱(8:30-10:00)**:verify 门 [19](RX 唤醒链,恰是
   "节拍落在 shell 处理中"的活证)追捕以来首绿的实机录屏;全量
   再跑门 [35] 又死=次核失踪案:-d int 的 CPU3 零执行证据、
   harness 内二分的现场还原、"回车挂起等门砸中引导尾"的动画
   演示、root-a 遮盖链的三重讽刺;守卫族常驻的取舍(常驻税 vs
   响亮第一案)。
8. **结案陈词(9:15-10:00)**:三条:守卫即战果;"悖论"先查
   取景框;槽位即语境,四种入口一个不能裸奔。结尾:68 站
   从零构建记录全公开;每修一层剥出下一层——下一个 panic 见。
