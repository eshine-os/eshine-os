# ls / 为什么打不开根目录:一个报障的三层解剖

用户在 bsh REPL 里打 `ls /`,busybox 报 "No such file or directory"。
`ls /etc` 却好好的。这封报障值得解剖三层。

## 第一层:ENOENT

我们的 ramfs 没有"/"实体节点(目录=前缀解析,站 40 的目录前缀柄)。
open("/") 走 rf_prefix_any("/") 判"根下有没有活名"——判定函数
rf_under 要求名字在前缀后紧跟 '/',即 b[dl]=='/'。根的 dl==1,
"/bin/hello" 的 b[1] 是 'b' 不是 '/'——判定恒假,根目录柄判死,
open 拿 ENOENT。

## 第二层:截名

把根判修活,`ls /` 出来的是 "/tc"、"/mp"——etc 丢了 'e',tmp 丢了
't'。枚举的名字起点又是 c=b+dl+1:子目录前缀 "/etc" 的名在斜杠后
(b+5 对),根前缀 "/" 已经含着斜杠(b+1 才是名)——统一的 +1 把
根项的名字截掉首字。

## 第三层:去重失效

再修,出来 etc×4、bin×10。首现去重循环里躺着同一对判定(深判+
名起点),每个候选都和"截了字的历史名"比较,永不相等,全部当
第一次出现。

三个症状、一个根:四处代码共享同一套"直接子项"判定,而这套判定
没有根特例。修法也就四处特判:rf_under 对 dl==1 恒真、深判豁免、
名起点 `dl==1?1:dl+1`。DT_DIR 的深径探测以完整路径作前缀,根下
语义本来就对,不动。

修完:`ls /` → tmp、etc、bin,各一次,exit code 0。场景 21/21。

目录逻辑的特例名单里,根目录永远排第一——它是最常见的边界,
也是最少被测试到的那个,因为"根"总在别人的测试里当前缀用,
很少当主角。
