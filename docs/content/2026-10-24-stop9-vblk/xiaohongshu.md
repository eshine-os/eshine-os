# 小红书:vblk 块设备站——内存即传输面,寄存器即门铃

## 正文(≤800 字)

第九站:guest 长出"存储"了 💾

先看结局:
dwrite → blk wrote
dread → blk read: ESHINE-BLK-persist
**销毁 VM → 重建 → 数据还在**
这是它第一次有"记性"。

本站最值钱的八个字:
**内存即传输面,寄存器即门铃** 🔑
- 512B 数据缓冲放 guest 自己的 RAM(它是唯一写者)
- 宿主经静态映射翻译,首次直访 guest 物理内存
- MMIO 只剩五个字:命令/地址/状态/容量/中断使能
- 大数据走内存,控制流走陷阱——不逐字搬运
这就是 virtqueue 的种子(下一站长成 virtio 真身 👀)

持久化怎么保证的?我一行保持代码都没写——
**磁盘是静态数组,根本不在 vm_create 的复位路径上**
"销毁重建数据还在"不是逻辑,是结构 💪
放对地方的东西,不需要维护

完整生命周期一次门铃走完:
请求 → 服务(同步,RAM 无延迟)
→ 置挂起 → 泵注中断 → ISR 清挂起 → 回报
(异步的只有"完成"这个动作)

还有个小工程哲学:第二个设备一落地,单设备的直查代码
立刻变成欠账——设备表化(dev 字段分发)自然到期 📋
