# 站 46:崩溃取证链(内容包口径)

## 一句话

一个用户进程野访,凭什么全 VM 陪葬?站 29 留下的边今天翻案:
野访者死它自己,死前留全遗照(硬件三元+寄存器+用户帧链)。

## 技术叙事(对外讲什么)

1. **连坐的废除**:EL0 无 VMA 野访从"全系统 panic"升"进程
   exit 链"——与信号终局同一台机器(fd 清+线程群扫+ZOMBIE)。
   内核自己的 bug 仍然全驻车:保守面留对了地方。
2. **遗照的内容**:crash 环 2 槽,每条 {tick,pid,名,esr/elr/far,
   code,x0-x5+x29,用户帧链前 4 帧}。ELF 核文件落盘不可为
   (ramfs 是只读 rodata 服务器)——内存记录+shell 倾倒是诚实形。
3. **走用户栈的三个门**:窗门(帧链不许出用户窗)+映射门
   (逐读前查 PTE present——坏栈不许把取证变成二次事故)+
   单调门(栈向高地址长)。观测工具的第一美德是不制造新事故。
4. **本站的雷**:-O2 用户码默认不链帧指针,首版 0 帧(x29 是
   残值);函数级 optimize 属性想局部开链,结果污染整个编译
   单元炸出 strlen。终修:demo 手工挂一帧 {x29,x30} 当法医
   夹具——真链用户构建(-fno-omit)同一机器即全链。
