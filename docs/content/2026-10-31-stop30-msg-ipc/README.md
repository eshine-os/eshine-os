# 站30 口径:微内核的对话机器

**eshine-os** · 站 30(三段消息 IPC)· 2026-10-31

## 本站做了什么

微内核的本命原语:**三段消息(Send-Recv-Reply)**。客户端发送即
阻塞,服务器收到处理后回执,回执值就是客户端的返回值——一次
对话、三步、零共享内存。外加异步脉冲(8B,不阻塞)、发送者超时
先走的 abort 协议(已收走则递 UNBLOCK 脉冲给服务器,QNX 镜像)。

六差距修复(参考实现普查列出的 QNX 差距)四项落码:
1. **coid 连接实体+引用计数**(连接有自己的生命周期);
2. **消息优先级传播**(客户端阻塞→服务器提速服务——门禁里
   prio-6 占先干扰正在跑,回复 dt=0 快返就是提权的活证);
3. **ChannelCreate flags**(CHF_UNBLOCK 门控 abort 通知);
4. **命名层级化**(路径分段比较)。
事件绑定族=v0 脉冲形;VM_SET 单拷窗=站 31(用户态 server)后议。

## 两个自雷(门禁自己抓的)

1. **rcvid 校验反谓词**:`rcvid & 0xF`(槽号+1,恒非零)写成
   拒绝条件——合法回执全数被拒,发送者恒满窗超时(dt=100
   定谳);
2. **三段语义搅锅**:demo 把"回执数据"和"返回值 status"共用
   变量,内核先写 42 再被返回值 0 覆写(reply 0 定谳)。

两雷都是判据面指向的:dt=100 说回执不到,reply 0 说变量搅锅——
**门禁先于修复**。
