# 站30 · X 8 连推

## 推 1(总览)
微内核的心脏:三段消息(Send-Recv-Reply)。客户端发送即阻塞,
服务器处理后回执,status 即返回值——一次对话三步零共享内存。
87 门 ×2 双绿收口。

## 推 2(abort 协议)
客户端等回执超时想先走:未收走=直接撤;已收走=内核递 UNBLOCK
脉冲给服务器,value=被持 rcvid。服务器下次 recv 就知道"那个
客户端不在了",持有的槽礼貌 REPLY 后静默释放——QNX unblock
镜像:死亡通知是协议的一部分。

## 推 3(优先级传播)
六差距修复②:客户端阻塞→服务器提速(QNX adjust_priority
镜像)。门禁怎么证?prio-6 占先干扰在跑,服务器 prio-20 不提
权永远让路;提权到 5,越过干扰服务,dt=0 写在判据输出里。

## 推 4(自雷①:rcvid 反谓词)
rcvid=(chid<<4)|(槽+1),低位恒非零。"低位非零才合法"被写
成 if(rcvid&0xF) return -22——合法回执全数被拒,客户端恒满
窗超时。dt=100 这个数字直接指向"回执根本没回来"。修:=!。

## 推 5(自雷②:三段搅锅)
demo 把回执数据和返回值 status 共用变量:内核先写 42,返回
值 0 又覆写。reply 0 直接指向"变量搅锅"。修:分家(r=status,
rv=data)。两雷都是判据面指向的——门禁先于修复。

## 推 6(机器复用红利)
RECV 的阻塞/超时/唤醒一行新逻辑没写:站 17 信号量机器
(rt_sem_take_to 阻塞+超时+重检环)整套复用。到达计数=信号量,
回执=每消息一信号量。好的原语层在这里给你红利。

## 推 7(六差距四落码)
参考实现普查列的 QNX 差距:①coid 实体+引用计数 ②消息优先级
传播 ③ChannelCreate flags(CHF_UNBLOCK) ④命名层级化(分段
比较)——四项落码;⑤事件绑定=v0 脉冲形 ⑥VM_SET=站 31 后议。
v0 中继=内核槽 64B,每拷贝都在对应进程的 SVC 语境,零跨址
空间 VA 访问。
