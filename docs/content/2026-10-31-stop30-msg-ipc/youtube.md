# 站30 · YouTube 口播稿

**[开场]**
微内核教科书都会告诉你:进程间通信用消息传递,不用共享内存。
但"消息传递"四个字背后的机器长什么样,只有自己造一遍才知道。
今天这一站,eshine-os 第三十站,我们把三段消息——微内核的
对话机器——落了码,八十七门两轮全绿。

**[三段消息的形状]**
先说形状。客户端调 MsgSend:消息拷进内核槽,自己挂起;服务
器调 MsgRecv:从通道取走消息,拿到一个 rcvid,一个回执句柄;
服务器处理完调 MsgReply:回复落槽,status 就是客户端 MsgSend
的返回值,客户端醒来。一次对话,三步,零共享内存。异步脉冲
是第四种元素:八字节的 code 加 value,不阻塞,服务器收到的
脉冲 rcvid 等于零。

**[abort 协议]**
最有味道的是 abort。客户端等回执超时了想先走,怎么办?如果
服务器还没收走消息,直接撤,干净利落;如果已经收走了,内核
给通道递一个 UNBLOCK 脉冲,服务器下次 MsgRecv 就知道——那个
客户端已经不在了。这是 QNX 的 unblock 镜像:死亡通知是协议的
一部分,不是异常处理。

**[优先级传播]**
六差距修复里最有意思的是优先级传播:客户端阻塞了,服务器就
该提速去服务。门禁怎么证?spawn 一个六优先级的占先干扰任务,
自旋一拍睡一拍;服务器优先级二十,数字大优先级低,不提权就
永远抢不过干扰。发送后不提权,回复 dt 就是满窗;提权到五,
越过干扰去服务,dt 等于零——传播的活证写在判据输出里。

**[两个自雷]**
冒烟第一轮 dt 等于一百,满窗超时。查下来不是没提权,是
rcvid 校验把合法回执全拒了:槽号加一恒非零,我把"非零才合法"
写成了"非零就拒绝"——一字之差,回执永不达。第二个雷:demo
把回执数据和返回值共用一个变量,内核先写四十二,返回值零又
把它覆写了。两个雷都是判据面指向的:dt 一百说回执没回,
reply 零说变量搅锅。门禁先于修复。

**[机器复用的红利]**
最后一件事值得单独说:RECV 的阻塞、超时、唤醒,我们一行新
逻辑没写。第十七站的信号量机器——阻塞、超时、重检环——整套
复用:到达计数是信号量,回执是每个消息一个信号量。好的原语
层会在这里给你红利。十七站前埋的种子,今天开花。
