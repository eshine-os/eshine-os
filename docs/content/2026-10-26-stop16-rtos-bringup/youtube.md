# YouTube/B 站分镜脚本 — 第十六站:RTOS 诞生 + 五幽灵之夜(约 18 分钟)

## 冷开场(0:00-1:30)
- 屏幕:三个异构客并跑的终端(RTOS ps 表 / 裸机对照组 / Linux 引导流)
- 口播:"今天 VM0 从 185 行裸机循环毕业。然后,藏了十五站的五个幽
  灵在一天内全部现身。这是这个项目开工以来最长的一天。"

## 第一幕:任务内核本体(1:30-6:00)
- 演示:ps 三任务(shell RUN/heartbeat SLEEP/idle)、spawn 问候即
  亡、sleep 3 期间心跳夹行
- 讲解:32 级位图 + ctz;统一任务帧 272B 的 elr 自描述(画图:IRQ
  帧/让出帧/首启动帧三源同构,一条 .Lpop 续跑)
- 坑1:noreturn 的 GCC 死代码(现场:空指针 FAR=0x18 的尸检截图)
- 坑2:空转语境缺 WFI 的热自旋

## 第二幕:五幽灵(6:00-11:30)
- 核心洞见:同源双镜像把共享物理面泄漏藏了十五站;异构第一天全爆
- 幽灵1 VBAR:vm1 引导换向量表 → vm0 中断跳错门 → "幽灵输出"
  (展示:boot 尾三行重演的 log + int 日志定位)
- 幽灵2 SCTLR 系:取指穿 Linux 页表翻到垃圾 IPA(展示:HPFAR 对
  不上向量页的故障报告)
- 幽灵4 GIC LR0:泵注入覆写 Linux 未认领 tick → jiffies 冻死(展示
  "停在首个 msleep"的现场 + LR0 恢复次序必须先于 WOKE 注入的教训)
- 总结图:五组帧收编,与 vtimer/sp_el0 同族

## 第三幕:陷阱量子的生灭(11:30-16:00)
- 起因:Linux 早期 PSTATE.I=1,时间片冻结,活客饿死
- 造物:512 陷阱/片双扳机抢占
- 翻车:关线 vs 挂起拍蒸发(画图:物理线驱动 HW LR pending,下一位
  客一装 vtimer,线落拍蒸发)
- 对照二分:基线 3/3 → 逐项加回 → 陷阱量子必闪断
- 决断:判据窗口挪到解掩蔽段,调度器整个拆掉
- 口播:"会造不难,会拆才是工程。"
