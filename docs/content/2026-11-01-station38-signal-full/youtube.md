# 站38 · YouTube 口播稿

**[开场]**
eshine-os 第三十八站,信号完整面。SA_RESTORER、sigqueue
携值、默认动作终止——但今天真正的主角,是一颗从第十六站
潜伏至今的过滤器,和它被引爆的全过程。

**[面上]**
先说做了什么。rt_sigaction 升级到四参数全脸:SA_RESTORER
语义,投递时把帧里的 x30 改写成 restorer,handler 一执行
完 ret 就落进 restorer,自调 sigreturn——这是 musl 二进制
真实的信号回栈方式,从此真兼容;旧的"handler 末尾显式调
sigreturn"契约继续有效,两立。sigqueue 带值,可以按 pid
也可以按 tid 定向,任务级的待决位图先于进程面解析。没有
handler 的信号,默认动作是终止:以 128 加信号号作为退出
码走 exit 链——POSIX 的脸。

**[谓词雷]**
然后是主角。sigqdemo 第一跑必挂:子进程打好"上床"日志,
睡两秒,永不醒。心跳照跳,虚拟时钟活着,睡客却醒不来。
一轮就定谳了:四条唤醒走查的过滤器,写的是 entry 非空。
那是第十六站"任务帧自铸"时代的活判据——fork 和 clone
的孩子们,从第二十九站起,永远 entry 为空,因为它们是帧
改写形。它们被所有唤醒走查永久排除在外。**二十二个站里,
没有任何一个 fork 子走过"自然睡"这条路,所以这颗雷一直
没响。本站第一个走新路的顾客到达,当天定谳。**修法:活
判据改成状态面。

这条规律值得写在墙上:谓词的时代错位,和新顾客的到达
无关——它一直在等第一个走新路的人。

**[流程账]**
这一站还集中清了三笔流程账:pkill 用模式匹配,把自己的
shell 连环杀掉——老坑再犯;站三十七调试时放跑的一个文件
系统扫描,后台烧了二十五分钟,负载上到十一,把线程 demo
的间歇楔又送上门——宿主污染窗这个家族第三次现身,站
三十六那个没定谳的失速档,也借此重新记档;自伤半径之内
构建产物集体失踪,三分钟全重建复原。教训沉淀到工具层面:
杀进程永远按 PID 精确点名;谈机制之前,先查负载。
