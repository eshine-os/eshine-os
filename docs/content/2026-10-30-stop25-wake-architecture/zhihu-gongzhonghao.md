# 我造的取证仪器,冤枉了我造的修复:一场三层翻案的仪器战争

> eshine-os 从零打造系列·第二十五站。上一站(站二十四)我们
> 把一个"Linux 卡顿"报障翻案成"输入蒸发"并收口了交互侧;
> 本站按登记清单去猎剩余的"静默 tick 停摆"真凶。结果真凶
> 没等到,等到了三重仪器伤——而最大的战果,是把这场冤案
> 完整写进了战报。

## 一、先证明,再动手:死亡帧不可达

站二十四收尾时,我们登记了一个头号残余:泊定帧出现
`reason=TIMER + ctl=0` 就是"[41] 闪断家族"的 vtimer 侧死亡
帧。本站第一件事不是写修复,是画状态机:

- 泊位分类和出口存档**同拍读同一个字段**——稳态泊帧必然自洽;
- PREEMPT 出口不改 reason 且 ws=0,下次 WAIT 出口必重分类;
- guest 侧存在合法的"自缴械"习语(站二十一的 rt_pend_disarm
  就是干这个的):ctl=0+cval 陈旧是健康缴械态。

所以"死亡帧"作为稳态不可达。站二十四那帧取证,是健康态被
误读。结论:为不可达状态写的修复是死代码,不落码(站二十二
的纪律:死码咬人)。

**先证明可达性再写代码**,这一步省下的是整个 B 块的无效工
作量——以及未来每个读这段代码的人的困惑。

## 二、修仪器,再谈修真凶

既然结论靠取证,仪器本身得先过硬。老的事件迹环只有 64 槽,
600 事件/秒下只余 0.1 秒历史——也就是说,站二十以来所有
vmtrail dump 都只是"即时尾巴",真正的死亡现场从来没进过环。
扩到 16K(≈27 秒窗),顺手把取证主链的并发纪律补齐:

- 环头原来是非原子 RMW,四核并写会丢事件、甚至拿旧字段冒充
  新条目(幽灵取证,直接污染证据)——收编进专用递归自旋锁;
- 每条证据行整行持锁,防靴流互插撕碎证据行;
- vmtrail 的 N 参数补多位解析+非数字 usage 拒绝——静默
  顶替默认值比报错更糟(站二十三同型坑的二连,我承认)。

然后是绊线的生灭:我最初设计了一个"泊定帧 cval 过期 >2s 自
动吐现场"的绊线,评审证明它真阳性路径为空(这类帧在扫描同
一迭代内必被唤醒)、假阳性可达(guest 写个远古 cval 就能触
发串口洪泛+永久解除武装)。砍掉。真仪器是两个:**门禁门红
自动取证**(verify 失败时逃逸→vmstat/vmrx/vmtrail 512 落日
志,覆盖全类失败脸)+**CARM-STALL**(后述,唯一可达坏类的
常设绊线)。

## 三、C 臂:一个真实可达的延迟类

泊定帧的唤醒,旧世界只押在 26/27 IRQ 驱动的扫描上。但物理
CNTV 是"当前客"的——别的 VM 一进场,装回自己的 ctx 就把
本核物理线覆写了,泊者挂起的 27 直接蒸发,唤醒迟至 1Hz 扫
描 = **tick 迟到最长 1 秒**(本应 µs 级)。

修法:泵扫描的 ws==1 复查网里加一条 vtimer 臂——saved
ctl 有 armed 且 cval 过期就置 WOKE,迟到 ≤1 泵圈。防热活锁:
同 cval 连醒 2000 次即停醒+CARM-STALL 一行标记(证据交门
禁自动取证)。

到这里,pending ⇒ runnable 在全部四类可交付事件(vtimer
过期/owner RX/virtio 完成/搁浅 SGI)上泵扫级成立:泊定
vCPU 任何漏醒 ≤1 泵圈自愈。

## 四、仪器战争:6/6"确定性回归"

C 臂落地的当晚,新写的普查探针报了 **6/6 确定性输入蒸发**。
前臂树 900 秒零失败,臂一落就 6/6——我把"C 臂是确定性回
归真凶"写进了战报,回滚臂做了 A/B 对照,两棵树**同样全挂**。

对着坏仪器做差分,差分必然也是坏的。两臂同挂恰恰在告诉我
挂因不在臂,但当时的我读成了"臂之外还有更大的雷"。直到
把 16K 迹环全量倒出来逐条对时间轴,三层真相才浮出来:

**第一层,探针自己的窗界正则。** 探针等锚先退出、再对窗口
内字节做正则。而 QEMU 的 chardev 以 ~16 字节为单位分块投
递,恰好把 "rtos: alive" 和 "tick=2" 劈在窗口边界两侧——
每一发回复的完整模式都横跨窗界,每一发都匹配失败。"6/6
确定性"是分块模式的确定性。我自己的记忆里就登记过这个坑
(站二十三"token 30ms 分块缝"),重蹈。

**第二层,宿主并发争抢。** 普查跑的时候,29 个评审代理正在
并发跑(给本站 spec 做对抗评审)。TCG 模拟下宿主一抢,QEMU
guest 直接掉到 6-18% 模拟速度,回复超窗。同一个争抢,还制造
了门禁 R-e 轮的"[36] tick 中途冻结"——那轮我初判"运行态
tick 停发类一记",本站收尾时**撤回**:3.0 秒的 demo 在 6%
速度下必然超 20 秒窗,签名与争抢伪象完全相容。门禁一折,
先查宿主负载,再谈机制。

**第三层,QEMU chardev 投递滞后。** 修真探针仍然偶发失收
(约 1/60)。这次取证彻底:失收那发的 **ev9(输入推入日志)
整组缺席**——ev9 是超级监控器每次把字节推入 guest 环时记
的见证位。它缺席,说明字节根本没进超级监控器,在 QEMU 侧
停了 3.2 秒;同期宿主壳照常泵转、逃生命令秒回。**失败在上
游,唤醒架构被自己的仪器洗清。**

三重都是仪器伤,一层不落全在树外。修真探针后:12 轮普查
11 绿,门禁双绿,臂无罪释放。

## 五、战报里最值钱的一行

这个项目做到第二十五站,最贵的不是任何一行修复代码,是几
条诊断纪律的反复验证:

- **判据先于结论**:6/6 不是结论,是测量;"确定性"三个字
  说的是测量仪器,不是被测系统;
- **仪器先于判据**:新探针必须先在已知好世界验证,再做
  差分;对着坏仪器的 A/B 是空对照;
- **假设判负也是战果**:R-e 的初判、C 臂的"回归",都先入
  档再翻案——翻案的证据(16K 迹环、ev9 见证位)正是本站
  仪器化升级换来的。

门禁 79 不变,终树双绿。下一站见。
