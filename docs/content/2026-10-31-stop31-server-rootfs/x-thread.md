# 站31 · X 8 连推

## 推 1(总览)
fd 不再是整数:它是通道三元组 {coid, ocb}——路由面=连接(哪个
服务器通道),状态面=ocb(这一打开在服务器侧的位置)。open/
read/write/close 全走三段消息往返,QNX resmgr 模型。88 门 ×2。

## 推 2(open 的解剖)
fdopen("/etc/motd") 的真相:查名表→建连接→路径打进 64B 消息
→ramfs 服务器查索引立 ocb→回执 ocb 号→{coid,ocb} 落 fd 表。
fd 不是"打开的文件",是"通往服务器的会话句柄"。

## 推 3(真 cpio)
rootfs=真 newc 格式:魔数 070701+110B 头+13 段 8 字符十六进制
域+4 对齐+TRAILER!!! 收卷。构建期 Python 打包目录树,汇编
.incbin 内嵌,内核 80 行解析器走卷索引逐路径挂名。非自制格式。

## 推 4(安全本义)
归档落内核只读区,用户窗不可见——文件内容只能经消息送达。
fd=通道三元组的隐含红利:文件服务是一个可以审计、可以替换的
服务器,不是内核里的隐藏特权面。

## 推 5(POCB 双侧镜像)
fork 继承 fd:客户端 coid 引用+1,同时发 DUP 消息让服务器
ocb 引用+1。单侧只加一半=悬空:父先 CLOSE 释放 ocb,子攥着
死号,别人 open 同号=文件位置串写。exit=逐 fd CLOSE 对称收口。

## 推 6(开机链)
参考实现 PM 形状:固定序列 tty→ramfs→pm,PM 绑 stdio 0/1/2 后
退场(一次性任务)。"PM 固定序列起步+协商位留后"——僵化审计
记档,不假装已经协商。
