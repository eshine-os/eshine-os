# fd 是什么?微内核给你的答案:通道三元组

(eshine-os 从零造 ARM64 Type-1 hypervisor+RTOS,站 31 记)

在 Linux 里,fd 是一个整数,0/1/2 是天经地义的 stdio。但这个
整数背后藏着什么?教科书不说,内核源码才说。在微内核(QNX)的
世界里,答案是:**fd 是一条通往服务器的通道的三元组**——
{coid, ocb},连接路由到哪个服务器通道,ocb 记录"这一打开"
在服务器那边的状态。今天这一站,eshine-os 把参考实现普查里的
"fdtable 与 同步队列件 的会合点"翻成了代码,88 门两轮全绿。

## open 一个文件,发生了什么

壳(用户态进程)调 fdopen("/etc/motd"):
1. 内核查命名表,找到 ramfs 服务器的通道,建一条连接(coid);
2. 把路径打进 64 字节消息,三段消息发给服务器;
3. ramfs 服务器解析路径,在自己打开的归档里找到文件,立一个
   ocb(每打开控制块:哪个文件+读到哪了),把 ocb 号回执;
4. 客户端把 {coid, ocb} 存进 fd 表——这个 fd 才诞生。

之后 fdread(fd) 就是:取 {coid, ocb}→发 READ 消息→服务器
从 ocb 的位置推进读 56 字节→回执里带数据。fdclose 是 CLOSE
消息+引用减一。**open/read/write/close 没有一行碰内存里的
文件,全部是消息往返**——resmgr(resource manager)模型的
本义。

## rootfs 是真的 cpio

不是自制格式:newc 磁带格式,110 字节头(6 字节魔数"070701"+
13 段、每段 8 个十六进制字符的域:inode/mode/filesize/
namesize……),名字补 4 对齐,数据补 4 对齐,TRAILER!!! 收卷。
构建期一个 40 行的 Python 工具把目录树打进归档,汇编 .incbin
内嵌进内核只读区;开机 ramfs 服务器 80 行解析器走卷索引+逐
路径挂名。归档落在内核区,用户窗根本看不到——文件内容只能
经消息拿到,这正是 fd=通道三元组的安全本义。

## POCB 引用计数:fork 教会我的事

fork 继承 fd 表,子进程和父进程共享同一个 ocb。谁管引用计数?
答案要**双侧镜像**:客户端的 coid 引用+1(连接有 8 份引用才
不会先关),服务器侧的 ocb 引用也要+1——靠一条 DUP 消息
告诉服务器"这一打开多了一个持有者"。只做单侧会怎样?父进程
先退出,CLOSE 把 ocb 释放了;子进程还攥着这个 fd,下次别人
open 拿到同一个号——两家的文件位置互相串写。exit 的镜像=
死亡关流:逐 fd CLOSE,服务器 ocb 引用减一。三层引用(fork
加、exit 减、close 释放)对称到字节。
