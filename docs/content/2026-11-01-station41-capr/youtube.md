# 站 41 · YouTube 口播稿

**[开场]**
eshine-os 第四十一站,能力框架,也是这个既定序列的终站。
这一站之后,这个内核里的每个进程都不再是全权裸奔——它们
上岗了,带能力。

**[机制面]**
能力就是一张四位位图:VFS、SPAWN、KILL、MM。规则三句话:
创建即零能力;只有开机壳拿到全权;fork 按位继承。而整个
系统里不存在任何"加能力"的路径——想改自己的能力,只有
一个方向:削。所以 self-inc-out 不需要执法,它由构造保证。
执法点设在几条咽喉要道上:六个 fd 操作判 VFS,fork 判
SPAWN,kill 判 KILL,mmap 那一族判 MM,缺能力即拒,默认
拒绝。再配上 rlimit——自己把 fd 上限降到三,第四次 open
就是 EMFILE——和创建期的随机 uuid:fork 出来的孩子继承
资源,但拿到一个全新的身份。

**[本站战果:一行被吞掉的调用]**
但今天真正想讲的,是把它做出来时埋进去的一颗雷。我往
sys_fork 里插两道新检查,一次编辑,把紧挨着的那行
rt_proc_create 吞掉了。替换,不是追加。下面那个 cp 成了
未初始化的野指针,下一行就把整个地址空间往野地址里拷——
数据中止,然后掉进这个内核的静默驻车:一条 wfi 死循环,
没有故障行,没有打印,整个系统安静地停在那里。

查它花了三个小时,路上三重伪象。尸检栈上读出信号量和
write 的返回地址,以为是活调用链——其实是早前打印留下的
陈栈。给任务状态上了硬件观察点,零命中——说明它从未阻塞、
从未被切走。全量断点陷阱集布好,一百九十秒,零停点——
优化器把一切内联,让"没停点"看起来像"没执行"。最后,
git diff 一照面,那一行,就在减号侧。

**[机器背书]**
最有讽刺意味的是:构建里 -Wall -Wextra 本来就在,吞行的
那次构建,GCC 必然打了"未初始化"警告。警告打了,没人读。
这是全费用里最便宜就能省掉的一课,却没省。freestanding
项目没有 -Werror 兜底,那构建输出就必须过眼。
