# 藏在开机 200 毫秒里的竞态:一次静默全链挂死的法医记录

站 50,给 eshine-os 的 RTOS 加日志持久化。这一站的代码两天就能写完,
但一个竞态让全链路静默挂死——复盘这篇,比功能本身值钱。

## 症状

busybox cat 任何文件:命令回显了,然后什么都没有。没有报错,没有
退出码,没有输出。不是必现——同一天同一个二进制,四连绿之后突然
全挂。

## 尸检

第一层:cat 没输出,但也没退出。顺藤摸到开机链的一行:
"srv: pm stdio bind failed"——PM 进程给 shell 绑 stdio(打开
/dev/tty 三次,拿 fd 0/1/2)失败了。

第二层:stdio 没绑上,loader 打开的文件占掉 fd 0/1/2,busybox cat
把读到的内容"写进自己的输出 fd"——而那个 fd 现在是它刚打开的
文件。写进了自己,控制台永远静默。

第三层:PM 为什么失败?PM 有 20 拍重试(200ms)。基线对照二分
(worktree 挂战役前提交,拷回 gitignore 的 busybox,强制重打包),
定谳:新改的 slogsrv 在自己的 boot 期就往 ramfs 发起了十几个阻塞
往返,这些往返和 PM 的 200ms 绑定窗同拍,把同优先级 FIFO 序打散。
间歇性,约五五开。

## 修法

不是加宽重试(那是遮),是**撤走竞争源**:slogsrv 的文件操作全部
惰性化——开机只挂名,第一次真正要写文件时(用户来写日志、或 1
秒周期收割到货)才建立连接、打开文件。boot 窗口里没有任何人会跟
PM 抢。

修完四连绿。场景里加了一条绊线:expect "pm bound stdio" +
fail_if "bind failed"——这个竞态再回来,第一步就会被咬住。

## 三条纪律进账

1. 竞态最爱藏在开机窗口——那里所有服务同时抢跑,谁慢一拍谁背锅。
2. 排障要对照:基线 worktree 一跑,嫌疑范围立刻砍半。别忘了
   gitignore 的产物要拷回来(还有 cp -a 会保留时间戳导致 make
   "已是最新"的假绿)。
3. make 的错误要过眼:并行构建时 objcopy 的"成功"尾行会盖掉
   前面的编译失败——同一天的第二个坑。

日志持久化本身?写进 /var/log,轮转保两个世代,kernel 源和
用户源同卷,cat 随时回读。机制不复杂,复杂的是让它老老实实活
在开机那 200 毫秒之后。
