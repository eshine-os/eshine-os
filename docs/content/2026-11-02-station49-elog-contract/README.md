# 站 49:eshine_log 日志契约(内容包口径)

## 一句话

给 hypervisor 和 RTOS 两个"操作系统"接上同一根日志神经——参考实现
三仓统一日志契约的 clean-room 站内形:一份共享核心,两套后端
钩子,同一套 LOG_INF()/LOG_DBG() 说同一门语言。

## 技术叙事(对外讲什么)

1. **契约先行**:冻结 ABI=级别枚举/模块结构/钩子签名。模块注册
   走 linker section(LOG_MODULE_REGISTER 在每个 .c 里放一个
   描述符,GNU ld 自动聚合成表)——不依赖构造函数,bare-metal
   EL2 环境安全。
2. **一处定义,两处编译**:common/ 单源,宿主与 RTOS 各编各的
   对象(一源两物),契约单源与构建隔离两立。
3. **运行时可调级**:loglevel elog dbg 一条命令,热路径日志当场
   打开——模块级过滤,不用重编不用重启。

## 金句

- 日志是系统的神经,不是 printf 的集合。
- 模块自己注册自己,链接器负责点名——运行时才数得清谁在说话。
- 静默的构建是最响的警报:make 报"已是最新"而新文件没编,
  先查谁劫持了默认目标。

## 数字

- 门禁 133→139;冒烟 24/24;双侧 ELF 模块段 0x20=2 模块;
  核心自带 vsnprintf 8 个转换符;32KiB 字节环。

## 战雷(给后来者)

Makefile 规则插在 all: 之前→它成了默认目标→make 只编一个文件
就"完成"了。规则落位在 all: 之后,是写构建脚本的第一纪律。
