# 站 53:debug/PMU 隔离(内容包口径)

## 一句话

把"两个 VM 共用一套硬件断点和性能计数器"这个审计定谳的病,治成
"机制就绪、平台实证"——真硬件上陷阱代访,QEMU 上平台存根兜底。

## 技术叙事

1. **机制**:MDCR_EL2.TDA 一位,EL1 的 debug 寄存器访问全部陷阱化,
   MDSCR per-VM 代访,断点/PMU 族 RAZ/WI。
2. **平台实证**:QEMU TCG 不实现这个陷阱(插桩零触发)——但它的
   debug 寄存器本来就是惰性存根,平台级无泄漏。
3. **头文件也会撒谎**:基准仓的位定义把 TPM 标在 bit0——那是
   HPMN 的地盘,写入后第三个子进程就挂死了。

## 金句

- 隔离机制要为真硬件而写,为当前平台而验。
- 撞上 HPMN 的位定义,就是撞上了一份没被验证过的文档。

## 数字

- 门禁 151→154;冒烟 14/14;MDCR_GUEST=0x200(仅 TDA)。
