# 我的 RTOS 学会"等待"了!还揪出一个潜伏一整站的 bug 🧨

今天 VM0 的任务内核补上最后一块拼图:
✅ 计数信号量(take 重检环,"唤醒=允许重试,非授予")
✅ 互斥锁(owner+递归+非拥有者拒绝)
✅ 每对象 FIFO 等待队列,唤醒即抢占
✅ 门禁 55→58 双绿

名场面 [27]:持锁者睡 300ms 的窗口里发 ps——
任务表里赫然一行 waiter prio 8 BLOCK
阻塞不是打出来的日志,是调度器账本里的活状态 📋

但首跑就炸,尸检惊悚:
🧵 -d int 显示弹出一个全零帧,eret 直奔 EL0 PC=0
🧵 帧基址 0xd430 对表 = "栈位 8",可任务池只有 0-7!
🧵 objdump 审完全部新代码——清白
🧵 回头读站 16 老代码:名字拷贝循环复用了 i,
   rt_frame_init 拿到的是【名字长度】当栈下标!!!

我的 RTOS 按名字长度发栈,活了两天:
shell(5字)住 stack[5],心跳(9字)住越界区,
全靠名字长度不撞车 🎲
第一对同长并发任务(producer/consumer 双 8 字)
共享一个帧区——当场对撞

教训:循环下标复用=静默杀手;两轮门禁绿≠无雷

另外如实记档:门禁 [53] 四轮一挂(Linux 解包步闪断,
站 16 关线丢拍残余),修法立为下一站首选,不刷绿不粉饰
