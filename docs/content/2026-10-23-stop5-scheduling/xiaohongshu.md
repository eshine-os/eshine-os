# 小红书:调度站——两个 VM 抢一个键盘

## 正文(≤800 字)

双 VM 第一次真并行,被一段"看起来无害"的注释整破防了 😤

第五站:调度。单核上让两台 VM 同时活,听着简单?
这一站的 bug 没有一个在模块里,全在模块的交互面——

🔥 名场面 1:两个 VM 抢一个键盘
我敲的宿主命令,落进了 guest 的 shell 执行 💀
共享输入面必须有唯一仲裁者,最后做成三态 HVC 代理:
有输入权回字符 / 有权没输入回 -1 / 没权回 -2(直接睡觉)

🔥 名场面 2:tick 之死(本站最狠)
源码怎么读怎么对,中断就是死了。
objdump 反汇编一开——某条 if 的分支里 EOI 调用凭空消失。
真相:补注释的时候,多行注释吞掉了单语句 if 的语句体,
EOI 变成"条件调用",宿主空闲段直接跳过 → 物理线不撤 →
GIC 认为中断永远在 → tick 只响了一声就没了。
源码看起来对 ≠ 汇编对,git-bisect 定文件,objdump 定罪 🕵️

🔥 名场面 3:睡了还攥着键盘
VM 睡觉前不还键盘 → 宿主读不到命令、调度器不敢跑别人
全系统死等一个永远不来的唤醒。
让位协议必须闭环:进等待,必放独占资源 ✋

还有一桩未破悬案如实交代:时基循环里计数器精确前进,
循环就是不退出,疑 QEMU 缓存交互,记录在案不追——
门禁判据改锚"跨量子次数",不锚时基 ⏱️

战果:spin 3G 迭代跨 7 个量子无损续跑,门禁 22 步三连绿 ✅
完整战况 devlog 05,每晚 1-2h 与 AI 从零造 Type-1。
