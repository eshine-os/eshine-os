# Devlog 07 — vtimer ctx 站（per-VM 上下文切换 + 多等待者）

日期:2026-10-23/24 · 版本:27.04-dev · 门禁:27 步真绿 ×2 连过

## 里程碑

还偏差 #10 的债：单等待者假设退役，双 VM 各自武装定时器、各自入睡、
各自按点醒：

    vm0> sleep 4     （先武装）
    vm1> sleep 2     （后武装）
    [vm1] slept (vtimer irq)    ← 后武装者先醒
    [vm0] slept (vtimer irq)    ← 先武装者后醒

单等待者时代"武者互相覆盖，先睡者永不醒"的回归线，从此是门禁
[19] 的位置断言（流内先后，不是分别等到）。

## 形态（用户批准 min-deadline 宿主仲裁）

- **切换对（参考实现同构）**：per-VM ctl/cval 内嵌帧尾；cortex-a57 是
  v8.0——**没有 CNTV 陷阱位**，guest 直写物理定时器，宿主只能以
  切换对齐：泵切入还本人 ctx、切出即存（全出口含 YIELD/EXIT/FAULT/
  WAIT）。物理 CNTV 从此恒为"当前客"的，无歧义。
- **每拍到期扫描**：物理线只为当前客响——别家的到期被错过。宿主
  tick（CNTHP 拍频 1s）扫 ctx 表，cval 过期者一律 WOKE。**拍频与
  泵粒度同阶不是妥协**：WOKE 的生效本就要等下一次泵轮到它——
  即时判定与 tick 判定在单核上是同一个时刻表。
- **醒后 ctx 熄火**：到期者 ctl 置 0——防下次切入装回过期 cval
  立刻重挂 27 风暴。

## 战况：表序找人的最后一次复发

首跑醒序反了：vm0（4s）先醒、vm1（2s）后醒。根因是第五站的
`sched_waiter` 残留——**双等待者下它按表序返回 vm0**，把 vm1 的
27 领给了 cval 根本没到的 vm0（假唤醒），真到点者靠下一拍扫描
补醒。"按状态找人不按当值找人"（第五站教训）在两源等待下的
完整形态是：**按 cval 过期找人**。27 归属改用与扫描相同的谓词，
`sched_waiter` 删除。

## 顺带修掉

- guest sleep 带参（`sleep [1-9]`）——多等待者判据需要不同时长。
- WAIT 原因判据从读物理 CNTV 改读**切出保存的本人 ctx**（物理
  此刻可能是他人视角——判据的数据源要跟所有权走）。

## 已知限制

- 到期精度 = 1 tick（扫描拍频；与泵粒度同阶，见上）
- 同一 guest 不得同时 armed vtimer 又等 RX（单源等待假设，帮助
  文本有 usage 提示）
